# Backend: fluxo Git

Siga a policy global: atualize `develop` e crie uma branch dedicada baseada nela antes de escrever qualquer arquivo, inclusive plano ou documentação. Não edite, commite, faça push ou integre diretamente em `develop`. Termine todo o escopo e as verificações na branch de trabalho; publique somente essa branch e abra PR para `develop`. Quando CI e proteções exigidas passarem, faça squash merge automaticamente pelo PR, sem aguardar nova solicitação; se houver aprovação humana obrigatória, mantenha o PR aberto aguardando-a. `master` espelha produção; promoção ocorre por fluxo de release separado. `main`, se existir, não é destino automático. Alterações de banco também devem atualizar os scripts SQL apropriados.
